# Visa Map — спецификация MVP

> Документ предназначен для реализации в Claude Code. Язык интерфейса — русский. Код, идентификаторы и комментарии в коде — английский.

## 0. Кратко

Клиентское приложение без бэкенда: интерактивная карта мира, на которой пользователь выбирает страну паспорта и видит визовый режим этого паспорта для каждой страны мира. Клик/тап по стране открывает детали. Данные статичные, нарезаны при сборке на чанки, загружаются параллельно и кэшируются в IndexedDB. Приложение mobile-first, устанавливается как PWA. Проект личный, хостинг — GitHub Pages (публичный репозиторий), без аналитики и мониторинга.

**Паспорта в MVP (3):** BY (Беларусь), KZ (Казахстан), US (США). Направления — весь мир.

**Вне рамок MVP:** аккаунты, бэкенд, i18n (только русский), нативные приложения и сторы, требования к документам, ссылки на МИД, история изменений режимов, аналитика, кастомный домен, сравнение паспортов.

---

## 1. Пользовательские сценарии

1. Открытие: выбран последний использованный паспорт (localStorage), по умолчанию BY. Карта серая и красится по мере прихода чанков.
2. Смена паспорта в селекте: карта сбрасывается в серый и красится заново (из кэша практически мгновенно).
3. Тап/клик по стране: открывается панель деталей (название, флаг, статус, срок пребывания, заметка). Карта центрируется на выбранной стране так, чтобы её не перекрывала панель.
4. Поиск страны по названию: выбор из результата = зум к стране + открытие деталей.
5. Вкладка «Список»: те же данные, сгруппированные по статусу, с поиском.
6. «Обновить данные»: очистка кэша, перезагрузка манифеста и текущего паспорта, с индикатором.
7. Оффлайн: приложение открывается (PWA), данные берутся из кэша, показывается дата данных.

## 2. Данные

### 2.1 Источник

**Passport Index Dataset** (GitHub, репозиторий `ilyankou/passport-index-dataset`), берётся tidy- или ISO3-вариант CSV. Данные исходно собраны с passportindex.org.

- **Формат проверен** на реальном файле `passport-index-tidy-iso3.csv` (`https://raw.githubusercontent.com/ilyankou/passport-index-dataset/master/passport-index-tidy-iso3.csv`): колонки `Passport,Destination,Requirement`, коды уже ISO alpha-3. Значения `Requirement`: `visa required`, `e-visa`, `eta`, `visa on arrival`, `visa free` (без срока), число дней (безвиз со сроком), `-1` (своя страна), `no admission`.
- **Покрытие:** BY, KZ и US присутствуют, по 199 записей на паспорт (включая свою страну). Записей `no admission` для этих трёх паспортов нет, красный цвет возможен только через оверрайды. Территорий (Гренландия, Пуэрто-Рико, Гвиана и др.) в датасете нет, см. 2.6. Косово (`XKX`) и Тайвань (`TWN`) есть.
- Нормализатор всё равно валидирует значения и падает на неизвестных (см. 2.4). Перед началом работы проверить дату последнего коммита в репозитории источника.
- Лицензия: проект личный, риск минимален. В README добавить ссылку на источник и его лицензию. Если проект станет публичным/монетизируемым, вопрос лицензии пересмотреть.

### 2.2 Сборка данных (build-скрипт)

Скрипт на TypeScript (Node, запуск через `tsx`), `scripts/build-data.ts`. Запускается в деплой-workflow (по push, по cron раз в неделю и вручную, см. раздел 9). Результат генерируется в `public/data` и публикуется вместе с приложением, **в репозиторий не коммитится** (`public/data` в `.gitignore`).

Шаги:
1. Скачать CSV.
2. Отфильтровать строки для паспортов из `scripts/passports.json` (`BY`, `KZ`, `US`). Добавление паспорта = добавление кода в этот файл.
3. Нормализовать статусы (см. 2.4).
4. Применить `data-src/overrides.json` (см. 2.5), оверрайды имеют приоритет над источником.
5. Достроить территории по `data-src/territories.json` (см. 2.6).
6. Разложить страны назначения по чанкам (см. 2.3).
7. Записать файлы, посчитать `version` каждого чанка как короткий хэш содержимого (чанк, не изменившийся между сборками, сохраняет версию и не перекачивается клиентом).
8. Записать `manifest.json`.
9. Валидировать результат схемами zod (те же схемы, что использует клиент, лежат в `shared/`), упасть с ошибкой при нарушении.
10. Сообщить в лог статистику: число стран по статусам на паспорт, страны без записи, страны без чанка, применённые оверрайды, достроенные территории.

### 2.3 Чанки

Группировка по субрегионам UN M49, слитым в 10 групп. Каждая страна попадает ровно в один чанк. Таблица соответствия `ISO3 → chunkId` хранится в репозитории (`data-src/chunks.json`), генерируется один раз из данных M49 и правится вручную для исключений.

| chunkId | Субрегионы M49 |
|---|---|
| `europe-west` | Western, Northern, Southern Europe |
| `europe-east` | Eastern Europe |
| `asia-west` | Western Asia |
| `asia-central-south` | Central Asia, Southern Asia |
| `asia-east-southeast` | Eastern Asia, South-eastern Asia |
| `africa-north` | Northern Africa |
| `africa-sub` | Sub-Saharan Africa |
| `americas-north` | Northern America, Central America, Caribbean |
| `americas-south` | South America |
| `oceania` | Australia and NZ, Melanesia, Micronesia, Polynesia |

Территории вне M49 или спорные (Косово, Тайвань, Западная Сахара, Гренландия и т. п.) назначаются в чанки вручную в `chunks.json`. Скрипт падает, если у страны из датасета нет чанка.

### 2.4 Нормализация статусов

Внутренние статусы: `visa_free`, `voa`, `evisa`, `visa_required`, `no_admission`, `self`, `unknown`.

| Значение источника | Статус | Поле `days` |
|---|---|---|
| Число дней или «visa free» | `visa_free` | число дней, если есть, иначе `null` |
| «visa on arrival» | `voa` | `null` (источник срок не даёт), уточняется оверрайдами |
| «e-visa», «eta» | `evisa` | `null` |
| «visa required» | `visa_required` | `null` |
| «no admission» | `no_admission` | `null` |
| маркер «своя страна» | `self` | `null` |
| прочее / отсутствует | `unknown` | `null` |

Неизвестные значения источника не молча превращаются в `unknown`: скрипт логирует их и падает в CI (чтобы изменение формата источника было замечено).

### 2.5 Оверрайды

Файл `data-src/overrides.json`: ручные правки поверх источника, ключ — пара «паспорт → направление».

```json
[
  {
    "passport": "BY",
    "destination": "KAZ",
    "entry": { "status": "visa_free", "days": 90, "note": "ЕАЭС: свободное пребывание по паспорту / ID" },
    "reason": "источник неточен для союзных режимов"
  }
]
```

Назначение: (а) режимы ЕАЭС и другие союзные случаи, где датасет может ошибаться; (б) красный статус «нет дипломатических связей / въезд закрыт», которого нет в источнике; (в) указание срока VOA в `note` (см. 3). Поле `reason` обязательное. Скрипт логирует применённые оверрайды и предупреждает, если оверрайд совпадает с источником (устарел).

**Начальный набор:** `US → PRK`: `no_admission` (паспорта США недействительны для поездок в КНДР; источник даёт `visa required`). Правки союзных режимов ЕАЭС и Союзного государства (BY, KZ, RU, KG, AM) добавляются после ручной проверки, пока не заполнены (см. раздел 13).

### 2.6 Территории

Территории, которых нет в датасете, показывают режим основной страны с пометкой. Файл `data-src/territories.json`:

```json
[
  { "territory": "GRL", "parent": "DNK" },
  { "territory": "PRI", "parent": "USA" },
  { "territory": "GUF", "parent": "FRA" },
  { "territory": "NCL", "parent": "FRA" },
  { "territory": "ATF", "parent": "FRA" },
  { "territory": "FLK", "parent": "GBR" }
]
```

Начальный список рассчитан на карту 110m; при переходе на 50m расширяется (Гуам, Бермуды, Свальбард и т. д.).

Правила достраивания:
- Запись территории = копия записи основной страны + поле `inheritedFrom: "<ISO3 родителя>"`.
- Если основная страна совпадает со страной паспорта (например, PRI для US), территория получает `self`.
- Если у основной страны статус `unknown`, у территории тоже.
- Оверрайд на саму территорию приоритетнее наследования.
- Территории, которые уже есть в датасете (HKG, MAC, PSE, TWN, XKX), не наследуют.
- Спорные территории (Западная Сахара, Северный Кипр, Сомалиленд) не наследуют, остаются серыми.
- Территория попадает в чанк по географии (GRL в `americas-north`, GUF в `americas-south` и т. д.), запись в `chunks.json` обязательна.
- Текст пометки хранится в клиенте, а не в данных: «Территория {страна}: показан режим основной страны, он может отличаться, проверьте отдельно».

### 2.7 Структура публикуемых данных

Генерируется в `public/data` при сборке, в репозиторий не коммитится.

```
/data
  manifest.json
  /BY
    index.json
    europe-east.json
    asia-west.json
    ...
  /KZ ...
  /US ...
```

`manifest.json`:
```json
{
  "schemaVersion": 1,
  "builtAt": "2026-09-21T03:00:00Z",
  "source": { "name": "passport-index-dataset", "url": "https://github.com/ilyankou/passport-index-dataset" },
  "passports": [{ "code": "BY", "iso3": "BLR", "name": "Беларусь" }]
}
```

`{passport}/index.json`:
```json
{ "passport": "BY", "chunks": [{ "id": "europe-east", "file": "europe-east.json", "version": "a1b2c3d4", "countries": 10 }] }
```

Файл чанка (ключ — ISO alpha-3 направления):
```json
{ "POL": { "status": "visa_free", "days": 90, "note": null, "inheritedFrom": null } }
```

Запись достроенной территории (например, `GRL` в чанке `americas-north`) отличается только полем `inheritedFrom: "DNK"`.

Коды стран везде ISO alpha-3 (карта на world-atlas использует числовые ISO 3166-1 id, в клиенте нужна таблица `numeric → alpha-3`).

Клиент при запросе `manifest.json` и `index.json` использует `cache: 'no-store'` / ревалидацию; чанки версионируются через query-параметр `?v={version}`, чтобы обойти HTTP-кэш GitHub Pages.

## 3. Цвета и статусы

| Статус | Цвет | Примечание |
|---|---|---|
| `visa_free` | зелёный `#2E9E5B` | в тултипе/панели указывается срок, если известен |
| `voa` | жёлтый `#F2C230` | всегда жёлтый независимо от срока (источник срок не даёт); срок при необходимости указывается в `note` через оверрайд |
| `evisa` (включая eTA) | светло-оранжевый `#F6B26B` | отдельный оттенок, чтобы отличать от визы в посольстве |
| `visa_required` | оранжевый `#EF8A2F` | |
| `no_admission` | красный `#D64545` | плюс ручные оверрайды «нет дипсвязей» |
| `self` | сине-серый `#4A6FA5` | страна паспорта |
| `unknown` / не загружено | серый `#C9CDD2` | |

Цвет **всегда** дублируется текстом (тултип на десктопе, панель деталей, вкладка «Список»). Отдельная поддержка дальтонизма (штриховка, специальная палитра) в MVP не делается. Территории с `inheritedFrom` красятся так же, как основная страна.

Легенда содержит 6 позиций (без `self` и серого — они поясняются отдельно или включаются по решению при реализации).

## 4. Клиентская архитектура

### 4.1 Стек

React + TypeScript + Vite, `d3-geo` + `world-atlas` (110m TopoJSON для старта) + `topojson-client`, Dexie (IndexedDB), zod, Zustand для состояния, `vite-plugin-pwa` (Workbox). Тесты: Vitest, Playwright. Линтинг: ESLint + Prettier. Менеджер пакетов: pnpm (или npm — на усмотрение).

### 4.2 Структура репозитория

```
/src
  /app            # корневой компонент, роутинг вкладок
  /data           # DataService, кэш (Dexie), схемы, загрузка
  /map            # MapView, проекция, зум/пан, hit-области
  /ui             # PassportSelect, SearchBox, Legend, DetailsSheet, CountryList, DataInfoBar, Menu
  /store          # Zustand store
  /lib            # статусы→цвета, ISO-таблицы, утилиты
/shared           # zod-схемы и типы, общие для клиента и build-скрипта
/scripts          # build-data.ts, passports.json
/data-src         # chunks.json, overrides.json
/public           # иконки PWA, манифест
/tests            # unit + e2e
/.github/workflows
```

### 4.3 Слои

- **DataService** — загрузка манифеста, индексов, чанков; кэш; версии; отмена; повторные попытки.
- **Store** — `passport`, `entries: Record<iso3, Entry>`, `chunkState: Record<chunkId, 'idle'|'loading'|'loaded'|'error'>`, `selectedCountry`, `dataBuiltAt`, `isRefreshing`.
- **MapView** — SVG, красит страны по `entries`, управляет зумом/паном.
- **UI** — шапка, поиск, панель деталей, список, легенда, меню.

### 4.4 Алгоритм загрузки паспорта P

1. Запросить `manifest.json` (no-store). Если `schemaVersion` отличается от сохранённого — сбросить кэш.
2. Взять `P/index.json` (из кэша, если `builtAt` не изменился, иначе запросить).
3. Запустить **все чанки параллельно**. Для каждого:
   - если в IndexedDB есть запись с той же `version` — взять из кэша;
   - иначе `fetch`, валидация zod, запись в кэш.
4. По приходу каждого чанка немедленно обновлять Store (не ждать `Promise.all`), карта красит страны этого чанка.
5. Порядок запуска: сначала чанк, к которому относится центр текущего вьюпорта, затем остальные (простая эвристика: сортировка чанков по расстоянию центроида до центра вьюпорта).
6. При смене паспорта — `AbortController.abort()` для незавершённых запросов; результаты чанков проверяют, что паспорт в запросе совпадает с активным, прежде чем писать в Store.
7. Упавшие чанки: состояние `error`, страны остаются серыми, показывается баннер «Не удалось загрузить часть данных» с кнопкой «Повторить» (перезапрашивает только упавшие).

### 4.5 Кэш (Dexie)

- Таблица `chunks`: ключ `[passport+chunkId]`, поля `version`, `data`, `fetchedAt`.
- Таблица `meta`: `schemaVersion`, `manifestBuiltAt`.
- TTL 30 дней: по истечении данные показываются из кэша, ревалидация идёт в фоне (stale-while-revalidate).
- Битая запись кэша (не проходит zod) удаляется и перекачивается.

### 4.6 «Обновить данные»

Очистить обе таблицы, запросить `manifest.json` с `cache: 'no-store'`, перезагрузить текущий паспорт. Кнопка заблокирована на время загрузки. Постепенное перекрашивание тоже видно (карта на время обновления сбрасывается в серый или показывает индикатор — решить при реализации, предпочтительнее не сбрасывать, а перекрашивать по мере прихода).

### 4.7 Эффект постепенной загрузки

CSS-переход `fill` 300 мс; внутри чанка стаггер 15–30 мс на страну. Стаггер не запускать во время pan/zoom. Уважать `prefers-reduced-motion` (отключить переходы).

## 5. Карта

- Проекция: Natural Earth (`d3.geoNaturalEarth1`). Антарктида (id 010) отфильтровывается.
- Сопоставление страна↔данные по ISO alpha-3; таблица соответствия числовых id world-atlas и alpha-3 хранится в `src/lib`. Страны на карте без записи в данных → серые, в панели «Нет данных». У некоторых фигур world-atlas (Косово, Северный Кипр, Сомалиленд) может не быть числового id: способ сопоставления определить на этапе 4 (по названию или вручную).
- Зум и панорама: pinch (два пальца), pan (один палец / мышь), колесо мыши, двойной тап — приближение. Реализация — `d3-zoom` или собственные pointer events. Масштабирование делать через `transform` на группе `<g>`, не пересчитывая `path`.
- На контейнере карты `touch-action: none`, чтобы браузер не перехватывал жесты.
- **Тап против драга:** смещение < ~8 px — тап, иначе панорамирование.
- **Микро-страны** (Сингапур, Мальта, Лихтенштейн, Монако, Багамы и др.): увеличенные прозрачные hit-области (или маркеры на зуме), плюс поиск и вкладка «Список».
- Кнопки «+», «−», «сбросить вид».
- Hover-тултип (название + статус) — только на устройствах с hover (`@media (hover: hover)`); на touch тап открывает панель.
- Выбранная страна подсвечивается обводкой.
- При выборе панель деталей не должна закрывать страну: карта смещается/центрируется в видимой части.

## 6. UI и мобильная адаптация

**Подход mobile-first.** Целевые размеры: от 360×640 и в ландшафте, десктоп — адаптация того же UI.

- **Шапка (компактная):** нативный `<select>` для паспорта (с флагом в тексте опции), поле поиска (иконка → раскрытие), кнопка меню «⋯» с пунктами «Обновить данные», «О данных» (дата сборки, источник, дисклеймер).
- **Вкладки:** «Карта» / «Список».
- **Панель деталей:** bottom sheet на мобильном (peek → half → full, закрытие свайпом вниз), боковая панель справа на десктопе. Содержимое: флаг, название, статус (цвет + текст), срок, note; для территорий (`inheritedFrom`) пометка из 2.6. В списке и тултипе такие записи помечены звёздочкой.
- **Легенда:** свёрнута по умолчанию (кнопка), по клику раскрывается.
- **Список:** страны, сгруппированные по статусу (безвиз, VOA, e-visa/виза, запрещён, нет данных), поиск по названию; тап по строке = выбор страны и переход на карту с зумом.
- **Размеры и вьюпорт:** `100dvh` вместо `100vh`; `viewport-fit=cover` и `env(safe-area-inset-*)`; тап-таргеты ≥ 44×44 px; страница не скроллится горизонтально.
- **Дата данных** («Данные от …») видна в меню/футере.
- **Дисклеймер:** «Информация справочная. Правила меняются, проверяйте на сайте МИД страны назначения». Показывается в «О данных» и в панели деталей.

## 7. PWA

- `vite-plugin-pwa`: precache оболочки приложения (JS/CSS/HTML, TopoJSON карты, иконки), `manifest.webmanifest` (name, short_name, иконки 192/512 + maskable, `display: standalone`, `theme_color`, `background_color`, `lang: ru`).
- Данные визовых режимов — в IndexedDB (не в SW-кэше), `manifest.json` данных запрашивается по сети с fallback на сохранённый.
- Корректный `base` для GitHub Pages (`/<repo-name>/`), scope SW соответствует.
- Обновление приложения: при новой версии SW показать ненавязчивый тост «Доступна новая версия — обновить».

## 8. Обработка ошибок

| Ситуация | Поведение |
|---|---|
| Чанк не загрузился | страны серые, баннер с «Повторить» только для упавших |
| Нет сети и нет кэша | пустая карта и сообщение «Нет соединения» |
| Нет сети, кэш есть | работает из кэша, показывается дата данных |
| Битый JSON / не прошёл zod | чанк считается упавшим, битая запись кэша удаляется |
| Страна на карте без записи | серая, в панели «Нет данных» |
| Неизвестный ISO-код в данных | пропускается, warning в консоль (в build — ошибка) |
| Смена паспорта во время загрузки | запросы отменяются, устаревшие ответы игнорируются |

## 9. CI/CD (GitHub Actions)

Публичный репозиторий, GitHub Pages как источник деплоя.

1. `deploy.yml`: триггеры push в `main`, cron (раз в неделю) и `workflow_dispatch` → установка зависимостей → `scripts/build-data.ts` (в `public/data`) → unit-тесты → сборка Vite → деплой на GitHub Pages (`actions/deploy-pages`). Если источник изменил формат, скрипт падает, деплой не выполняется, на Pages остаётся предыдущая рабочая версия.
2. `ci.yml`: на PR — lint, typecheck, unit-тесты, e2e Playwright (в т. ч. touch-профили).

## 10. Тестирование

- **Unit:** нормализация статусов (включая неизвестные значения), маппинг статус→цвет, применение оверрайдов, распределение стран по чанкам (нет стран без чанка, нет дублей).
- **Unit DataService:** кэш-хит, кэш-мисс, смена версии чанка, отмена при смене паспорта, частичный сбой, битая запись кэша, сброс по `schemaVersion`, TTL/фоновая ревалидация (с моком `fetch` и `fake-indexeddb`).
- **E2E (Playwright):** основной сценарий на десктопе и на эмуляции touch (профили iPhone и Pixel): открытие → покраска → смена паспорта → выбор страны → «Обновить данные» → оффлайн-режим.

## 11. Критерии приёмки

**Данные и загрузка**
- Первая покраска происходит до загрузки последнего чанка.
- Повторное открытие с прогретым кэшем не запрашивает чанки (только `manifest.json`).
- «Обновить данные» реально перекачивает всё (видно в Network).
- Падение одного чанка не мешает остальным; «Повторить» перекачивает только упавшие.
- Смена паспорта не оставляет на карте цветов предыдущего.
- Для каждого из 3 паспортов покрыты все страны, которые есть в исходном датасете.
- Территории из `territories.json` окрашены как основная страна и помечены в панели деталей.

**Мобильный интерфейс**
- Работает на 360×640 и в ландшафте без горизонтального скролла страницы.
- Pinch/pan плавные (цель ~60 fps на среднем Android), страница не зумится и не скроллится под картой.
- Любую страну, включая микро-страны, можно выбрать за ≤ 3 действия (поиск или зум + тап).
- Bottom sheet не перекрывает выбранную страну.
- Тап-таргеты ≥ 44×44 px.

**PWA**
- Приложение устанавливается на главный экран и открывается оффлайн (оболочка + кэш данных).

**Качество**
- Lighthouse (mobile): Performance ≥ 90, Accessibility ≥ 90, PWA — все проверки пройдены.
- Цвет всегда сопровождается текстом статуса; проверка через Chrome DevTools («Emulate vision deficiencies») подтверждает, что статус читается без цвета.

## 12. План реализации (этапы для Claude Code)

1. **Каркас:** Vite + React + TS, ESLint/Prettier, Vitest, структура репозитория, `shared/` со схемами zod.
2. **Данные (build):** скачивание и разбор CSV, нормализация, `chunks.json`, `overrides.json`, `territories.json`, генерация `public/data`, unit-тесты нормализации и чанков.

4. **Карта:** отрисовка world-atlas, таблица ISO, покраска по `entries`, легенда, статичная (без жестов).
5. **Жесты и мобильный UX:** zoom/pan/pinch, тап-против-драга, микро-страны, кнопки зума, `dvh`/safe-area.
6. **UI:** PassportSelect, bottom sheet / боковая панель, поиск, вкладка «Список», меню, баннеры ошибок, «Обновить данные», дата данных, дисклеймер.
7. **Постепенная покраска:** стаггер, приоритет чанка по вьюпорту, `prefers-reduced-motion`.
8. **PWA:** service worker, манифест, иконки, тост обновления.
9. **CI/CD:** два workflow (`deploy.yml` с cron-сборкой данных и деплоем на GitHub Pages, `ci.yml`).
10. **E2E и полировка:** Playwright (десктоп + touch), Lighthouse, README (источник данных, лицензия, дисклеймер, как добавить паспорт).

## 13. Принятые решения и открытые вопросы

**Принято**
1. Формат источника проверен на реальном файле (см. 2.1).
2. VOA всегда жёлтый, условие «≤ 30 дней» снято (источник срок не даёт).
3. Проекция Natural Earth, Антарктида скрыта; отдельная поддержка дальтонизма вне MVP.
4. Данные генерируются в деплой-workflow и не коммитятся в репозиторий.
5. Территории наследуют статус основной страны и помечаются как «может отличаться» (см. 2.6).
6. Красный цвет только через оверрайды; стартовая запись `US → PRK`.

**Открыто**
1. **Оверрайды ЕАЭС и Союзного государства** (BY, KZ, RU, KG, AM). В источнике сейчас: BY→RU 90 дней, KZ→RU 90 дней, BY→KZ 90 дней, KZ→BY безвиз без срока. Какие пары править, определяет владелец проекта после ручной проверки.
2. Дополнительные красные оверрайды для BY, KZ, US (пополняются вручную по мере обнаружения).
3. Свежесть источника: проверить дату последнего коммита в репозитории датасета до начала работы.
4. Сопоставление фигур world-atlas без числового id (Косово, Северный Кипр, Сомалиленд): решить на этапе 4.
5. Расширение `territories.json` при переходе на карту 50m (после MVP).
